# WALKTHROUGH

A linear tour of the crbgc.org codebase: what runs, in what order, and why each piece is
shaped the way it is. It was generated by the `code-walkthrough` skill; the note at the end
says how to treat it.

## 1. Overview

This repository builds and serves **crbgc.org**, the governance site of the Common & Recent
Bogeymens Golf Club. It is a Hugo static site with no theme, no client-side JavaScript, and
one hand-written stylesheet. Everything rendered comes from Markdown in `content/` and Go
templates in `layouts/`. The output is served as static assets by a Cloudflare Worker,
whose one script exists to rebuild the site every Monday.

There is no application entry point in the usual sense. The entry points are:

- **`wrangler.jsonc`'s `build.command`**, the whole build: a format check, a CSS lint, a
  validation pass, then the production `hugo` build into `public/`. It is the only
  definition of the build gate. Workers Builds runs it on every push, `task deploy` runs
  it before deploying, and `task check` runs it through a dry run.
- **`worker.js`**, the Worker. Its `fetch` handler hands every request back to asset
  serving, and its `scheduled` handler fires on a Monday cron to trigger a rebuild.
- **`Taskfile.yml`**, the developer-facing commands: `setup`, `format`, `check`, `serve`,
  `icons` and `deploy`.

The site publishes five content sections and several machine-readable outputs:
`/index.xml`, `/llms.txt`, `/sitemap.xml`, `/robots.txt`, and two section feeds. A current
build:

```
                  │ EN
──────────────────┼────
 Pages            │ 90
 Paginator pages  │  0
 Non-page files   │  0
 Static files     │  6
 Processed images │  0
 Aliases          │  1
 Cleaned          │  0
```

_(Transcript of `hugo --gc --panicOnWarning`, run while authoring.)_

The 90 pages are 77 regular pages (66 notes, 5 governance documents, 4 news posts, 1 notice
and 1 set of minutes) plus section, home and 404 pages. The six static files are the seal,
the favicon in three forms, the Open Graph card, and `_headers`. The single alias is a
redirect left behind by a retitled news post.

## 2. Architecture

```
content/          Markdown; five sections plus the homepage
  governance/     bylaws, standing rules, special rules of order, officers,
                  and the draft Rules of Golf
  notices/        meeting and bylaw-amendment notices (expire)
  minutes/        meeting minutes (approved / draft)
  news/           dated posts
  notes/          66 essays — the Club's informal writing
layouts/          Go templates; no theme; hand-formatted
  _default/       baseof, plus the dated-post list/single that news and notes use
  governance/     list by weight; single with adoption dates
  minutes/        list grouped by year; single with the meeting record
  notices/        list split current/expired; single with "Shown through"
  partials/       item-row, the notices split, the build-time validator
  home.rss.xml    the site feed, forked from Hugo's embedded template
  index.llms.txt  plain-text index for machine readers
  robots.txt      crawler rules and content signals
assets/css/       one stylesheet, Biome-managed, piped through Hugo Pipes
static/           seal, favicons, link-preview card, _headers
hugo.toml         permalinks, disabled kinds, output formats, locale
wrangler.jsonc    the Worker: build gate, assets, cron, custom domain
worker.js         the Worker's only code
bunfig.toml       formatter configuration
```

**Data flows one way and stays shallow.** Frontmatter fields drive template branches
directly. There are no taxonomies (`disableKinds` removes taxonomy and term pages), no
`slug:` anywhere, and no content store beyond Hugo's own page collections.

`hugo.toml` — `[permalinks]`

```toml
[permalinks]
notices = "/notices/:slug/"
minutes = "/minutes/:slug/"
news = "/news/:slug/"
notes = "/notes/:slug/"
```

Two cross-cutting rules shape most of the template code. Both are worth holding in mind
before reading further:

1. **The title is the URL** in the four dated sections. `:slug` falls back to the
   normalized title when no `slug:` is set, and none ever is, so title, URL segment and
   filename are one string. `governance` is deliberately absent from `[permalinks]`, so its
   URLs come from the filename instead.
2. **Every notices _listing_ goes through one partial.** A notice expires, and a listing
   that works out "recent notices" for itself drifts back into showing expired ones.

## 3. From push to published: the build gate

Every deploy runs one string, wherever it starts:

`wrangler.jsonc` — `build`

```jsonc
  "build": {
    "command": "bunx bun@1.4.4 fmt --check && bunx biome check assets && hugo --buildFuture -D --renderToMemory --gc --panicOnWarning && rm -rf public && hugo --minify --gc --panicOnWarning",
  },
```

It has four stages, cheapest first, and each gates the next:

1. **`bun fmt --check`** checks the formatting of everything outside `layouts/` and
   `assets/` (§11). bun is pinned through `bunx` because the build image's own bun may
   predate 1.4.4, the first release with `bun fmt`.
2. **`biome check assets`** formats and lints the stylesheet.
3. **The validate pass** renders the full site in memory with drafts (`-D`) and
   future-dated posts (`--buildFuture`) included. Both flags are load-bearing. The
   validator (§4) iterates `.RegularPages`, which excludes drafts and future posts from a
   default build, so without them a post written ahead of time would go unchecked until
   the day it publishes.
4. **The production build** writes into a freshly emptied `public/`, because Hugo never
   prunes it.

The comment above `build` in `wrangler.jsonc` carries the reason for each flag. They live
there because this string is the gate's only definition. The Taskfile does not repeat it:
it calls it.

`Taskfile.yml` — `check`

```yaml
  check:
    desc: Run the deploy's own build gate (wrangler.jsonc build.command) without deploying
    cmds:
      - bunx wrangler deploy --dry-run
```

A dry run executes the custom build, bundles the Worker, and stops before uploading:

```
task: [check] bunx wrangler deploy --dry-run
[custom build] Running: bunx bun@1.4.4 fmt --check && bunx biome check assets && hugo --buildFuture -D --renderToMemory --gc --panicOnWarning && rm -rf public && hugo --minify --gc --panicOnWarning
[custom build] All 100 files are formatted.
[custom build] Checked 1 file in 24ms. No fixes applied.
[custom build] Total in 22 ms
[custom build] Total in 26 ms
Total Upload: 0.52 KiB / gzip: 0.35 KiB
Your Worker has access to the following bindings:
env.ASSETS         Assets
--dry-run: exiting now.
```

_(Transcript of `task check`, run while authoring and filtered to its key lines.)_

Workers Builds, Cloudflare's git integration, runs the string on every push. A push to
`main` follows it with `bunx wrangler deploy`. Any other branch follows it with
`bunx wrangler versions upload`, which builds and validates but publishes nothing and has
no preview URL, because `preview_urls` is off. `task deploy` runs `bunx wrangler deploy`
from a Mac, after reading a Cloudflare API token from the keychain if one is there. The git
connection, the branch deploy commands and the `HUGO_VERSION=latest` build variable live in
the Cloudflare dashboard, not in the repo. README's "Cloudflare settings" section records
them.

## 4. The validator runs first

Before any markup, the base template calls the validator. This is the most load-bearing
file in the repository and the least visible, because it renders nothing.

`layouts/_default/baseof.html` — `head`

```go-html-template
<!doctype html>
<html lang="{{ .Site.Language.Lang }}">
  <head>
    {{- partialCached "validate-content.html" . -}}
```

`partialCached` with no variadic key means it runs **once per build**, not once per page.
The call sits in `<head>` because every page inherits `baseof.html`, so Hugo cannot render
any page without passing through it.

`layouts/partials/validate-content.html` makes three passes.

**Pass 1: Obsidian wikilinks.** This pass runs over `site.Pages`, which includes governance
documents and section `_index.md` files. The notes arrived from an Obsidian vault, and
Goldmark renders `[[Target]]` as literal brackets: the build would exit 0 and the page
would publish with the markup visible.

`layouts/partials/validate-content.html` — wikilink check

```go-html-template
{{- range site.Pages -}}
  {{- if .File -}}
    {{- if strings.Contains .RawContent "[[" -}}
      {{- errorf "%s: contains an Obsidian wikilink ([[...]]) — Hugo publishes these as literal brackets. Write a root-relative link instead, e.g. [Label](/notes/some-slug/)." .File.Path -}}
    {{- end -}}
  {{- end -}}
{{- end -}}
```

`RawContent` excludes frontmatter by construction, so only the body is checked.

**Pass 2: heading-fragment citations.** Cross-document links carry anchors, as in
`/governance/bylaws/#article-iv--officers`. Goldmark derives those anchors from heading
text, so editing a heading would silently break every inbound citation: the link would
still resolve, just to the top of the page.

`layouts/partials/validate-content.html` — fragment check

```go-html-template
{{- $byURL := dict -}}
{{- range site.Pages -}}
  {{- $byURL = merge $byURL (dict .RelPermalink .) -}}
{{- end -}}
{{- range site.Pages -}}
  {{- if .File -}}
    {{- $file := .File.Path -}}
    {{- range findRESubmatch `\]\((/[^)#\s]*)#([^)\s]+)\)` .RawContent -}}
      {{- $path := index . 1 -}}
      {{- $frag := index . 2 -}}
      {{- $key := cond (hasSuffix $path "/") $path (printf "%s/" $path) -}}
      {{- with index $byURL $key -}}
        {{- if not (in .Fragments.Identifiers $frag) -}}
```

Pages are indexed by `RelPermalink` rather than by content path, because the two disagree
for governance and section pages. A fragment link whose path matches no page fails as well,
with its own message.

Two limits are visible in the code:

- The regex requires a `#`, so a plain `](/notes/x/)` is never looked up. Of the 151
  root-relative links in content, 9 carry a fragment.
- The header comment names the other: `.Fragments` knows content headings only, so a
  fragment pointing at an id emitted by a template would be reported as missing. None
  exist today.

**Pass 3: per-page rules over every regular page.**

`layouts/partials/validate-content.html` — page loop header

```go-html-template
{{- $seen := dict -}}
{{- range sort site.RegularPages "File.Path" -}}
  {{- $section := .Section -}}
  {{- $file := .File.Path -}}
```

The loop names no sections. Rules that belong to one section are gated on `$section`, so a
section added later is checked without being listed anywhere. Sorting by file path is
deliberate: when two files claim one URL, the same file is reported every time. `.ByDate`
would not do, because nothing stops two posts sharing a date, and a bare date carries no
time, so which file got named would drift between builds.

The first rule is that **every post outside governance carries a date**. Governance is
excluded because its documents are atemporal. An undated post would otherwise publish,
render its list row as "January 1, 0001", and be missing from the site feed forever (§9
shows why).

Next comes **the identity check, which branches on section**. It is the one place the
"title is the URL" rule is not uniform:

`layouts/partials/validate-content.html` — identity check

```go-html-template
  {{- $seg := path.Base .RelPermalink -}}
  ...
  {{- if eq $section "governance" -}}
    {{- $want := urlize .Title -}}
    {{- if ne .File.ContentBaseName $want -}}
      ...
    {{- end -}}
  {{- else -}}
    {{- if ne .File.ContentBaseName $seg -}}
      ...
    {{- end -}}
  {{- end -}}
  {{- with index $seen .RelPermalink -}}
    {{- errorf "%s: URL /%s/%s/ is already taken by the earlier post %s — retitle this post." $file $section $seg . -}}
  {{- end -}}
  {{- $seen = merge $seen (dict .RelPermalink $file) -}}
```

- **Dated sections.** The URL segment comes from the title, so requiring the filename to
  equal it catches a retitle that was not accompanied by a rename. That is the edit that
  silently moves a published URL.
- **Governance.** The segment _is_ the filename, so that comparison would be vacuous.
  Instead the check normalizes the title with `urlize` and compares it to the filename, so
  a retitle there still has to be accompanied by a rename.
- **Any section not listed in `[permalinks]`.** It falls into the `else` branch, where the
  comparison is just as vacuous as it would be for governance, and nothing checks its title.
- **Duplicate URLs.** The `$seen` dict catches two files that claim one URL. With flat
  directories and the filename check alongside it, that mostly happens through a
  subdirectory copy, which nothing else would catch: Hugo builds both pages cleanly.

The rest of the loop checks frontmatter vocabularies and pairs:

- `notice_type` and `meeting_type` must each be one of their documented values;
- a notice with a `meeting_date` must also carry `expires`, and `expires` must fall after
  the meeting;
- `approved: true` in minutes requires `approved_on`.

Every one of these fails the build. Here is each one firing, from deliberately broken
copies:

```
ERROR notes/probe-wiki.md: contains an Obsidian wikilink ([[...]]) — Hugo publishes these as literal brackets. Write a root-relative link instead, e.g. [Label](/notes/some-slug/).
ERROR notes/probe-frag.md: link to /governance/bylaws/#article-xx--nothing — /governance/bylaws/ has no heading with that anchor. Goldmark derives anchors from heading text, so retitling a heading breaks every citation of it.
ERROR notes/probe-undated.md: no date — a post in a dated section must carry one. Without it the page publishes but never reaches /index.xml, and its list row renders January 1, 0001.
ERROR notes/probe-misnamed.md: filename does not match its URL segment "probe-name" — Hugo derives the URL from the title, so rename the file to probe-name.md (note that Hugo drops & entirely; write "and" if you want it in the URL).
ERROR notes/sub/1744-golf-rules-modernized.md: URL /notes/1744-golf-rules-modernized/ is already taken by the earlier post notes/1744-golf-rules-modernized.md — retitle this post.
ERROR governance/bylaws.md: title "Constitution and Bylaws" normalizes to "constitution-and-bylaws" but the filename is "bylaws" — governance URLs come from the filename, so either restore the title or rename the file to constitution-and-bylaws.md. Renaming moves a URL that other documents cite: add the old path under aliases: and check the citations.
ERROR notices/notice-of-2027-annual-meeting.md: notice_type "anual-meeting" is not one of the four documented values (annual-meeting, special-meeting, previous-notice, bylaw-amendment)
ERROR notices/notice-of-2027-annual-meeting.md: meeting_date with no expires — a meeting notice must stop being current after its meeting. Set expires to the day after meeting_date.
ERROR notices/notice-of-2027-annual-meeting.md: expires 2027-06-21 is not after meeting_date 2027-06-21 — expires is the first day the notice is hidden
ERROR minutes/minutes-2026-annual-meeting.md: approved: true with no approved_on — both move together; set approved_on to the date the minutes were adopted
```

_(Transcripts of `hugo --buildFuture -D --renderToMemory --gc --panicOnWarning` against
planted files and edits in a scratch copy of `HEAD`, one at a time.)_

The duplicate message's advice, "retitle this post", fits the case of two posts sharing a
title. It does not fit the subdirectory copy shown here, and it can point at the wrong file
when a new post takes an existing post's title. In that case the new file sorts first,
fails the filename check, and also claims the URL in `$seen`. The published post is then the
one told to retitle.

`errorf` fails the build on its own; a planted typo exits 1 without `--panicOnWarning`.
That flag is there for Hugo's own warnings, which are advisory by default: without it a
template lookup failure would publish a broken section and exit 0.

## 5. The page shell

With validation passed, `baseof.html` renders the shell every page shares: a `<title>`, the
description, canonical and Open Graph tags, icons, the stylesheet, a header with the seal
and nav, `main`, and a footer.

`layouts/_default/baseof.html` — head metadata

```go-html-template
    {{ $ogType := cond .IsHome "website" "article" }}
    {{ $ogTitle := cond .IsHome .Site.Title .Title }}
    <link rel="canonical" href="{{ .Permalink }}" />
    <meta property="og:type" content="{{ $ogType }}" />
    <meta property="og:title" content="{{ $ogTitle }}" />
```

The values are computed into variables first rather than inlined. That way an inline
`if/else` never sits inside a `content="…"` attribute, where a line break would become part
of the value. The comment above them carries the rest of the reasoning: the site exists to
be cited, so a link preview should come from the page itself, and `og:image` is one card
for the whole site that must be an absolute URL.

The stylesheet goes through Hugo Pipes with subresource integrity:

`layouts/_default/baseof.html` — stylesheet

```go-html-template
    {{ $style := resources.Get "css/style.css" | minify | fingerprint }}
    <link
      rel="stylesheet"
      href="{{ $style.RelPermalink }}"
      integrity="{{ $style.Data.Integrity }}"
    />
```

The fingerprint puts a content hash in the filename, which is what lets `static/_headers`
mark `/css/*` immutable for a year (§10).

The header's seal is an `<img>` rather than inline SVG, so its traced path data is not
shipped on every page. The nav is one link block ranged over the five section names:

`layouts/_default/baseof.html` — nav

```go-html-template
      {{ $section := .Section }}
      <nav class="site-nav">
        {{ range slice "notices" "minutes" "news" "notes" "governance" }}
          <a
            href="{{ printf "/%s/" . | relURL }}"
            {{ if eq $section . }}aria-current="page"{{ end }}
            >{{ title . }}</a
          >
        {{ end }}
      </nav>
```

`title` produces each label from the section name. `$section` is captured before the
`range` because `.` is rebound inside it. The footer's copyright range ends at
`{{ now.Year }}`, so it never goes stale.

## 6. The homepage

`layouts/index.html` is curated rather than a mirror of the nav. It lists notices, news
and governance, and deliberately omits minutes and notes. Each list holds its own query:

`layouts/index.html` — notices section

```go-html-template
  <section>
    <h2>Latest notices</h2>
    {{ with first 3 (partial "notices-by-status.html").current }}
      <ul class="item-list">
        {{ range . }}{{ partial "item-row.html" . }}{{ end }}
      </ul>
    {{ else }}
      <p class="muted">Nothing yet.</p>
    {{ end }}
```

Notices come from the `current` half of the split (§7), never from the section directly,
because "most recent 3" would silently include expired notices. News takes the same shape
with `first 5 (where site.RegularPages "Section" "news").ByDate.Reverse`. Governance ranges
over the section `ByWeight`.

The page has **no `h1`**. That is a design choice, reaffirmed rather than overlooked;
`content/_index.md` supplies the opening prose instead.

## 7. The notices split

`layouts/partials/notices-by-status.html` is the only place the expiry rule is computed.
It renders nothing and returns a dict.

`layouts/partials/notices-by-status.html`

```go-html-template
{{- $now := now -}}
{{- $current := slice -}}
{{- $expired := slice -}}
{{- with site.GetPage "/notices" -}}
  {{- range .RegularPages.ByDate.Reverse -}}
    {{- if and .Params.expires (lt (time .Params.expires) $now) -}}
      {{- $expired = $expired | append . -}}
    {{- else -}}
      {{- $current = $current | append . -}}
    {{- end -}}
  {{- end -}}
{{- end -}}
{{- return dict "current" $current "expired" $expired -}}
```

Three consequences:

- **A notice with no `expires` is current forever.** It falls to the `else` branch, so
  absence means permanent. The validator (§4) allows that only for a notice with no
  `meeting_date` either, which is how a notice of motion or a standing notice is written.
- **`expires` is the first day the notice is _hidden_**, not the last day it is shown. That
  is why `notices/single.html` renders the day before it, under the label "Shown through",
  rather than the raw value.
- **`now` is evaluated at build time.** A notice moves from current to expired only when the
  site is rebuilt, which is one of the two reasons for the Monday rebuild (§10).

Three callers consume the partial:

- the homepage (§6);
- `layouts/notices/list.html`, which renders both halves, with the expired notices under
  their own heading;
- `/llms.txt` (§9).

## 8. Section pages and metadata

A section has its own template only where it has something of its own to say. News and
notes have nothing beyond a date, so they render through the `_default` pair:

`layouts/_default/single.html`

```go-html-template
{{ define "main" }}
  <article>
    <h1>{{ .Title }}</h1>
    <p class="post-date">
      <time datetime="{{ .Date.Format "2006-01-02" }}">
        {{ .Date.Format "January 2, 2006" }}
      </time>
    </p>
    {{ .Content }}
  </article>
{{ end }}
```

`_default/list.html` renders `.Pages.ByDate.Reverse` through `item-row.html`. Because both
`_default` templates are used by about 70 pages on every build, a new section inherits a
layout that is known to work rather than an untested fallback.

The other three sections each ship both templates:

- **Lists.**
  - `minutes/list.html` wraps the same row list in `(.Pages.GroupByDate "2006").Reverse`,
    giving each year its own heading.
  - `governance/list.html` orders `ByWeight` and prints each document's description beside
    its link, because those documents are atemporal and their order is editorial.
  - `notices/list.html` is the §7 consumer.
- **Singles.** Each holds its metadata `<dl>` inline, between the title and the content:
  - `notices/single.html`: posted date, type, meeting date, and "Shown through".
  - `minutes/single.html`: meeting date and type, approval status (with the `approved_on`
    date when approved), presiding officer and secretary, and the present and absent
    rosters.
  - `governance/single.html`: adoption and amendment dates, and no `<dl>` at all when a
    document has neither. The draft Rules of Golf and the Officers page have neither
    today.

`layouts/partials/item-row.html` renders one row, and decides the approval badge from the
data rather than from the section:

`layouts/partials/item-row.html` — approval badge

```go-html-template
  {{ if isset $p.Params "approved" }}
    {{ if $p.Params.approved }}
      <span class="badge approved">Approved</span>
    {{ else }}
      <span class="badge draft">Draft</span>
    {{ end }}
  {{ end }}
```

It uses `isset` rather than `with` because `approved: false` is meaningful and must render
"Draft"; `with` would skip it. Only minutes carry the field, so only minutes rows get a
badge, but nothing restricts the field to minutes.

`layouts/404.html` is the one page with no section; §10 shows how it is served.

## 9. The machine-readable outputs

`hugo.toml` gives the homepage three output formats:

`hugo.toml` — output formats

```toml
[outputFormats.llms]
mediaType = "text/plain"
baseName = "llms"
isPlainText = true
notAlternative = true

[outputs]
home = ["html", "rss", "llms"]
```

`isPlainText` matters: it routes rendering through `text/template` rather than
`html/template`, so nothing is HTML-escaped.

**`/llms.txt`.** `layouts/index.llms.txt` defines one section template and calls it five
times:

`layouts/index.llms.txt` — `llms-section`

```go-html-template
{{- define "llms-section" -}}
{{- with .pages }}
## {{ $.heading }}
{{ range . }}
- [{{ .Title }}]({{ .Permalink }}){{ with .Description }}: {{ . }}{{ else }}{{ with .Date }} — {{ .Format "2006-01-02" }}{{ end }}{{ end }}
{{- end }}
{{ end -}}
{{- end -}}
```

What each section passes:

- **Governance:** `.Pages.ByWeight`.
- **Notices:** `first 15` of the `current` half from §7.
- **Minutes and news:** `first 15` of their pages, newest first.
- **Notes:** `.Pages.ByTitle`, with no cap. The call site explains the difference:
  `/llms.txt` is an index rather than a feed, so alphabetical order serves a machine reader
  scanning for a topic.

Every line uses `{{-`/`-}}` trim markers deliberately, because whitespace in this template
is output.

**The site feed.** `layouts/home.rss.xml` is a fork of Hugo's embedded `rss.xml`. Its header
comment lists exactly three changes, and the first is the reason for the fork:

`layouts/home.rss.xml` — page selection

```go-html-template
{{- $pages := where site.RegularPages "PublishDate.IsZero" false -}}
{{- $pages = $pages.ByPublishDate.Reverse -}}
```

Hugo's default page order puts any page with a nonzero `weight` ahead of every page without
one, regardless of date. The governance documents carry `weight` to order their list page,
so they led the feed, three of them stamped year 0001 (#54). Selecting dated pages
explicitly fixes that. It is also why an undated post would vanish from the feed, which is
the reason §4 rejects one.

The other two changes:

- the author and copyright branches are dropped, because nothing sets them;
- `lastBuildDate` is dropped, because it had no honest value once `lastmod:` was removed.

The feed keeps expired notices. That is the documented exception to the notices rule: a
feed is an archive, and items are never removed from one.

**Section feeds.** Hugo gives every section an RSS feed by default. Three of the five turn
theirs off in their `_index.md`, each with its reason inline:

`content/notices/_index.md` — frontmatter

```yaml
outputs: ["html"] # no feed: a notices listing must go through notices-by-status.html (#55)
```

`governance` does the same because a chronological feed of atemporal documents means
nothing, and `notes` because the site feed already carries every note. Only
`/minutes/index.xml` and `/news/index.xml` remain.

**Crawlers.** `enableRobotsTXT = true` makes Hugo render `layouts/robots.txt`. It allows
everything, declares content signals permitting search, AI input and AI training, and points
at the sitemap, which Hugo generates on its own.

## 10. Serving: the Worker and the Monday rebuild

`wrangler.jsonc` binds `public/` as the Worker's static assets:

`wrangler.jsonc` — `main` and `assets`

```jsonc
  "main": "./worker.js",
  "assets": {
    "directory": "./public",
    "binding": "ASSETS",
    "not_found_handling": "404-page",
  },
```

Requests are answered from `public/` before any code runs, and `404-page` makes a miss
return Hugo's `404.html` with a 404 status. The rest of the file restricts the Worker to
the custom domain: no `workers.dev` address and no preview URLs. Workers Logs is on, so a
failed cron leaves an error behind for three days.

The Worker's code is one object:

`worker.js` — default export

```js
export default {
  fetch: (request, env) => env.ASSETS.fetch(request),

  async scheduled(controller, env) {
    const response = await fetch(env.DEPLOY_HOOK, { method: "POST" });
    if (!response.ok)
      throw new Error(`deploy hook answered ${response.status}`);
  },
};
```

`fetch` handles only a request that matched no file and reached the script. Per the file's
header comment, it goes straight back to asset serving, which answers with the 404 page.

`scheduled` is the reason the script exists. It runs on the cron in `wrangler.jsonc`,
`"0 9 * * 1"` (Mondays 09:00 UTC), and POSTs the Worker's own deploy hook, whose URL is the
secret `DEPLOY_HOOK`. Workers Builds then runs §3's build from `main`. Throwing on a non-OK
response turns a failed hook into a failed invocation that Workers Logs records.

That rebuild is what makes time-based content work on a static site:

- **A future-dated post** is left out of the production build, which has no
  `--buildFuture`. It appears on the first Monday on or after its date, unless a merge or
  `task deploy` publishes it sooner.
- **A notice** crosses into "Expired" only when `now` is re-evaluated (§7).

`static/_headers` is copied into `public/` unchanged, and Cloudflare reads it as
response-header rules:

`static/_headers`

```
# Hugo fingerprints everything under /css/, so a changed file gets a new name.
/css/*
  Cache-Control: public, max-age=31536000, immutable
```

## 11. Formatting and the toolchain

Formatting is split by what each tool can parse. `bun fmt` takes everything it can, Biome
takes the CSS, and `layouts/` is formatted by hand.

`bunfig.toml` — `[fmt]`

```toml
[fmt]
# Leave fenced code in Markdown alone: a Hugo snippet quoted in a note or in
# WALKTHROUGH.md is a quotation, and formatting it would change what it says.
embeddedLanguageFormatting = "off"
# layouts/ is Go templates, which bun fmt cannot parse; they are hand-formatted.
# assets/ is CSS, which Biome formats and lints.
ignorePatterns = ["layouts/**", "assets/**"]
```

The exclusions live under `ignorePatterns`, so `task format` and the build gate can both
call bare `bun fmt` with no glob. `bun fmt` also skips whatever `.gitignore` ignores, so
`public/`, `node_modules/` and `.wrangler/` need no entry here. What remains in scope is
100 files:

- the Markdown in `content/` and the repo root;
- the project skills under `.claude/`;
- `hugo.toml`, `bunfig.toml`, `worker.js`, `wrangler.jsonc` and `Taskfile.yml`;
- the JSON configs.

`task format` is the writing counterpart to the gate. It runs `bun fmt`, then
`bunx biome check --write assets`. Locally, `bun` is the Homebrew one from the `Brewfile`;
only the build gate pins a version.

The other tasks:

- `setup` installs the Brewfile and the one devDependency.
- `serve` runs `hugo server -D --buildFuture`.
- `deploy` is described in §3.
- `icons` regenerates the favicon rasters and the Open Graph card from the two SVG sources,
  `static/favicon.svg` and `static/seal.svg`.

Authoring has its own tooling under `.claude/`. The `new-notice`, `new-minutes` and
`new-news` skills scaffold frontmatter for each dated section and finish with
`bun fmt <file>`. `.claude/rules/notes.md` carries the dating rules for notes.

## 12. Things worth knowing that the code does not say

- **A Go template comment ends at the first `*/`.** Writing a glob such as a wildcard
  directory followed by `/single.html` inside `{{/* … */}}` fails the build with "comment
  ends before closing delimiter". Several comments in `layouts/` are long enough that this
  is a live hazard.
- **The templates were machine-formatted until #150** and are hand-formatted now. Some
  layout in them is a leftover of the old formatter rather than a choice, such as each nav
  link's closing `</a` with its `>` on the next line. Whitespace inside a tag or a `{{ }}`
  action is not output, so it renders the same either way.
- **A note needs both a `date:` and no `draft:`.** The two move together. The date half is
  a build failure (§4). The `draft:` half cannot be checked, because a draft is not built in
  production: a dated note that keeps `draft: true` simply never appears.
- **A new section needs `[permalinks]`.** Without it the section's URLs come from filenames,
  and §4's identity check compares the filename with itself.
- **Hugo floats.** Neither the `Brewfile` nor the build image pins it
  (`HUGO_VERSION=latest`), so a breaking release appears as a failed build rather than a
  silent change.
